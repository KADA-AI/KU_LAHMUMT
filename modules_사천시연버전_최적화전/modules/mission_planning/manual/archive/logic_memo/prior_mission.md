# 선행임무 로직 메모

## 목적
이 문서는 현재 `modules/mission_planning`에 구현된 **선행임무 재계획** 동작을
운용 시나리오 기준으로 정리한 메모다.

범위는 아래와 같다.
- 선행임무 입력이 들어왔을 때 어떤 UAV를 선택하는가
- 선택된 UAV의 기존 임무는 어떻게 분리되는가
- 선행임무 자체는 어떤 형태로 생성되는가
- 다른 UAV들은 어떻게 이어서 임무를 수행하는가
- 최종 MissionPlan/IMP/FlightPath는 어떤 구조가 되는가

---

## 1. 선행임무가 시작되는 조건
선행임무는 `0202 PriorMissionInfo`가 들어오고,
monitoring이 이를 level-4 재계획(`0902`)으로 올렸을 때 시작된다.

현재 선행임무는 두 종류를 처리한다.

1. `missionType = 1`
- 좌표지향 선행임무
- 특정 좌표를 우선 확인해야 하는 상황

2. `missionType = 2`
- 표적추적 선행임무
- 특정 `targetID`를 가진 표적을 우선 추적해야 하는 상황

이 재계획은 일반 재계획처럼 여러 옵션을 만드는 형태가 아니라,
기본적으로 **선행임무 반영 1안**으로 처리된다.

---

## 2. 어떤 UAV가 선행임무를 수행하는가
선행임무는 UAV 한 대를 골라 끼워 넣는다.

### 2.1 좌표지향 선행임무
- 목표 좌표가 있으면
- 현재 UAV 상태(snapshot) 기준으로
- **그 좌표에 가장 가까운 UAV**를 선택한다.

### 2.2 표적추적 선행임무
우선순위는 아래와 같다.

1. `targetInfo`에 해당 `targetID`를 보고 있는 watcher UAV가 있으면
- 그 UAV를 우선 선택

2. watcher가 없거나 targetInfo에 없으면
- 표적 좌표 기준 가장 가까운 UAV를 선택

즉 표적추적 선행임무는
"이미 그 표적을 보고 있던 UAV가 있으면 그 기체를 계속 쓰고,
없으면 가장 가까운 UAV를 새로 붙이는 방식"이다.

---

## 3. 선택된 UAV의 기존 임무는 어떻게 바뀌는가
선행임무를 맡은 UAV는 기존 임무를 지우지 않는다.
현재 수행 중이던 개별임무를 **세 조각**으로 다시 만든다.

- `기존 임무의 완료 구간(done)`
- `선행임무(prior)`
- `기존 임무의 잔여 구간(resume)`

즉 구조는 아래와 같다.

- 원래: `A`
- 재계획 후: `A_done -> prior -> A_resume`

이 구조를 쓰는 이유는 두 가지다.

1. 이미 수행한 임무를 시각화에서 보존하기 위해
2. 선행임무를 끝낸 뒤 원래 하던 임무를 자연스럽게 이어가기 위해

---

## 4. 완료 구간(done)은 어떻게 남기는가
선행임무를 맡은 UAV의 기존 path는 현재 시점 기준으로 잘린다.

잘라내는 기준은 아래 순서다.

1. `currentWaypointID`가 있으면
- 그 waypoint 이전까지는 완료 구간으로 본다.

2. `isDone=True`가 waypoint에 찍혀 있으면
- 완료된 WP는 done으로 넘긴다.

3. monitoring이 기록한 sweep 진행도가 있으면
- 이미 수행한 촬영 sweep도 resume 쪽에서 추가로 잘라낸다.

4. resume이 비게 되면
- 마지막 유효 waypoint라도 남겨서
- 임무 체인이 끊기지 않게 한다.

### 4.1 done path는 왜 남겨두는가
done path는 실제 수행용이 아니라,
- 이미 어디까지 수행했는지 보이게 하고
- 기존 임무가 갑자기 사라져 보이지 않게 하기 위한 성격이 강하다.

또한 필요하면 done path 끝에
**replan anchor waypoint**를 하나 추가해
시각적으로 재계획 시점의 위치가 끊기지 않게 한다.

---

## 5. 선행임무(prior)는 어떻게 생성되는가
선행임무용 개별임무와 path는 새로 생성된다.

### 5.1 좌표지향 선행임무
성격:
- 특정 좌표를 지향하는 정찰/확인 임무
- 목표 좌표 중심의 loiter 구조

현재 특징:
- 개별임무는 좌표 리스트 기반으로 생성
- path는 목표 지점 중심으로 만들어짐
- loiter 시간이 포함됨
- 목표 좌표의 altitude가 비어 있으면 DEM으로 보정 가능

### 5.2 표적추적 선행임무
성격:
- 특정 표적을 따라가며 추적하는 임무
- auto-tracking 중심

현재 특징:
- 개별임무에 `targetID`가 들어감
- flight path의 목표 WP에도 `autoTracking.targetID`가 반영됨
- 단일 target loiter 성격으로 생성됨
- 추적 시간은 현재 300초 기준

### 5.3 선행임무 path의 현재 형태
현재 선행임무 path는
길게 진입해서 여러 점을 도는 구조보다,
**목표점 중심의 짧은 임무**에 가깝다.

즉 현재 구현은
- 좌표/표적 지점으로 들어감
- 그 지점에서 일정 시간 선행임무 수행
- 이후 원래 임무로 복귀
라는 구조로 이해하면 된다.

---

## 6. resume 임무는 어떻게 복원되는가
선행임무를 마친 뒤,
선행임무를 수행한 UAV는 원래 하던 임무를 이어서 해야 한다.
이를 위해 `A_resume` 개별임무와 path를 새로 생성한다.

resume은 단순 복사본이 아니다.
아래를 반영한다.

- 현재 waypoint 이후만 남김
- 이미 완료된 WP 제거
- 이미 수행된 sweep 제거
- 필요 시 현재 위치 anchor 추가

즉 resume은
"원래 임무의 남은 부분만 다시 만든 재개용 임무"다.

---

## 7. 다른 UAV들은 어떻게 되는가
선행임무를 맡지 않은 UAV들도 그냥 기존 임무를 처음부터 다시 하지는 않는다.
이 기체들은 **done/resume 구조만** 적용한다.

즉 구조는 아래와 같다.

- 원래: `B`
- 재계획 후: `B_done -> B_resume`

차이점은,
선행임무를 수행하는 UAV처럼 중간에 `prior` 임무가 끼워지지 않는다는 것이다.

### 7.1 다른 UAV 처리 목적
이 로직의 목적은 아래 두 가지다.

1. 이미 끝난 구간을 다시 수행하지 않도록 하기
2. 재계획 시점 이후의 임무만 이어서 수행하게 하기

### 7.2 trimming 기준
다른 UAV들도 아래를 기준으로 path를 자른다.

- `currentWaypointID`
- `isDone`
- sweep 진행도

즉 공격 재계획에서 쓰는 resume 철학과 매우 유사하다.

---

## 8. 최종 산출물 구조
선행임무 재계획이 끝나면 아래가 새로 만들어진다.

### 8.1 선행임무 수행 UAV
- 새 `MissionPlan`
- 새 `IndividualMissionPackage`
- `done path`
- `prior path`
- `resume path`

개별임무 목록은 대체로 아래 순서를 가진다.
- 기존 앞부분 개별임무들
- 완료 처리된 기존 임무 조각(done)
- 선행임무(prior)
- resume 임무
- 뒤쪽 원래 개별임무들

### 8.2 다른 UAV
- 새 `IndividualMissionPackage`
- `done path`
- `resume path`

즉 모든 UAV가 새 IMP를 받지만,
실제 새 임무를 끼워 넣는 것은 선택된 UAV만이고,
나머지는 기존 임무를 잘라 이어가는 구조다.

---

## 9. 자동 적용 방식
선행임무는 일반 재계획 옵션 선택형과 다르게,
생성이 끝나면 **직접 적용**되는 흐름을 가진다.

현재 의도는 아래와 같다.
- 새 MissionPlan 생성
- `0301`, `0305` 정리
- `0903`으로 수행 임무 갱신 요청
- 필요 시 `0702(ignore=2)`를 함께 보내 적용 누락을 방지

즉 선행임무는
운용자가 별도 옵션 선택을 다시 하지 않아도,
만들어진 계획을 바로 적용하는 흐름에 가깝다.

---

## 10. 현재 구현 철학 요약
현재 선행임무 로직은 아래 철학으로 이해하면 된다.

1. 선행임무는 기존 임무를 덮어쓰지 않는다.
2. 기존 임무는 `done / prior / resume` 구조로 재조합한다.
3. 선행임무를 맡지 않은 UAV들도 현재 시점 기준으로 잘라서 이어간다.
4. 표적추적 선행임무는 공격 재계획의 tracking UAV 구조와 유사하다.
5. 시각화는 유지하고, 실제 수행은 아직 안 한 부분만 이어서 하게 만든다.

즉 선행임무는
"기존 협업기저임무를 깨지 않고,
중간에 우선 확인해야 할 임무를 삽입한 뒤,
나머지 임무를 다시 이어서 수행하게 만드는 재계획"이다.
