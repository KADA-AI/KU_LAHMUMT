R-DSS-SFR-0210 유무인기 상태정보 기반 재계획(TRR 검증 메모)
------------------------------------------------------------
목적: DSPS-SS-0210/SFR-0210 요구(유무인기 상태정보 활용 재계획) 충족 여부를 TRR에서 검증하기 위한 근거와 시연 포인트를 정리한다.

요구/설계 매핑
- 요구: 유무인기 상태정보를 반영해 임무를 재계획하고, 결과를 정보관리 모듈에 저장.
- 설계 결정사항 코드 근거:
  · 상태정보 수신/활용: modules/monitoring_ver2/logic/monitoring_logic_part.py
    - 0401(agentStatus) 수신 시 agentStateList에서 health/coordinate/fuel 점검 → _update_health_based_availability → 가용 기체 세트 계산.
    - 0402(targetInfo) 수신 시 update_target_info_from_0402 → targetInfo.json 갱신, 신규 표적은 replan trigger로 accumulate.
    - 0802(강제/고장) 수신 시 _handle_mandatory_command → _set_aircraft_availability(비가용/복귀) → run_replan_procedure() 트리거.
  · 재계획/0902 생성: modules/monitoring_ver2/logic/replan_actual_logic.py
    - run_replan_procedure → judge_replan_situation → manage_replan_triggers → determine_level_and_send_request
    - confirmed_request 기반으로 replanLevel/replanReason/optionList/inputMissionIDList 구성 후 0902 push, final_replan_output 로직스토어 업데이트.
    - ensure_replan_level_details_file(replanInfo.json) 준비 및 target mark used.
  · 가용성 저장: modules/monitoring_ver2/utils/vehicle_status.py::write_vehicle_status → Logs/<Scenario>/.../VehicleStatus/status.json 작성.
  · 재계획/표적 스냅샷 저장: modules/monitoring_ver2/logic/replan_utils.py::ensure_replan_level_details_file/ensure_target_info_file → DSS_Internal/replanInfo.json, targetInfo.json 유지.

1. 유무인기 상태정보 기반 임무 재계획 기능 분석
1.1 유무인기 상태정보 수신 및 활용 구조
  - 0401 agentStatus 수신 → health!=1, 좌표/연료 결측 시 해당 기체 unhealthy로 표시 → availability_health_block에 반영.
  - baseline(시작 시 저장된 기체 ID) + mandatory override(0802) + unhealthy 집합을 종합해 _recompute_availability() 수행, logic_store.set_data("availability_baseline") 로 GUI 표시.
  - MonitoringTab에서 항공기 가용 상태 라벨링(modules/monitoring_ver2/gui/tabs/MonitoringTab.py)으로 사용자 확인 가능.
1.2 유무인기 위치정보를 활용한 재계획
  - agentStateList의 coordinate 필드 유효성 검증을 availability 판단에 사용(좌표 결측 시 비가용 처리) → 재계획 시 후보 기체 제외 로직으로 간접 반영.
  - targetInfo(0402) 좌표 스냅샷을 targetInfo.json에 유지하며 신규 표적 발생 시 replan_situations에 push → run_replan_procedure에서 0902 생성 시 detail 포함.
  - prior_mission_replan 등에서 좌표지향/표적추적(replan_reason=좌표지향) 텍스트 구성으로 위치 활용 근거 기록.
1.3 고장정보 기반 가용성 판단 및 재계획
  - agentState.health != 1 또는 강제 명령(0802 mandatoryType 1/2) 수신 시 _set_aircraft_availability(False) → availability 재계산.
  - 비가용 변경 시 로그 “[MON_LOGIC] availability…” 기록, systemMode 3/4일 때 run_replan_procedure 즉시 호출.
  - ReplanTab에 UAV 고장/페이로드 고장 규칙 표시(modules/monitoring_ver2/gui/tabs/ReplanTab.py), replan_reason에 고장 텍스트 삽입.
1.4 재계획 결과 저장 및 정보관리 모듈 연계
  - replan_utils.ensure_replan_level_details_file → DSS_Internal/replanInfo.json 유지(상태, lastUpdated, latestTarget 등).
  - targetInfo.json(0402 기반), VehicleStatus/status.json(가용성 스냅샷) 모두 db_paths 경로(Logs/<Scenario>/SBC3/…)에 저장 → 정보관리 모듈과 동일 루트 공유.
  - determine_level_and_send_request에서 final_replan_output을 logic_store에 남기고 push_store에 0902 본문 보관(모듈 내부 조회/GUI 표시용).

TRR 시연/검증 포인트 (권장 절차)
1) 상태정보 수신/가용성 반영
   - 0401 샘플 송신(health=1, 좌표 포함) → MonitoringTab 가용 라벨 “가용” 확인, VehicleStatus/status.json 갱신 확인.
   - health=0 또는 좌표 누락 상태 송신 → 해당 기체 “비가용” 전환, availability_baseline/health_block 로그 확인.
2) 위치정보 활용 재계획
   - 0402 targetInfo 신규 표적 좌표 송신 → replan_situations 목록 추가, 0902 생성 시 replanDetail에 trigger=0402 좌표 포함되는지 확인, targetInfo.json 업데이트 확인.
3) 고장 기반 재계획
   - 0802 mandatoryType=1/2 입력 → 기체 비가용 처리 및 즉시 run_replan_procedure 실행 여부 로그 확인, 0902 replanLevel/Reason에 강제/고장 문구 포함 확인.
   - mandatoryType=3(복귀) → 비가용 해제 및 재계획 트리거 동작 여부 확인.
4) 결과 저장/연계
   - 0902 발행 후 DSS_Internal/replanInfo.json 존재 및 최신 timestamp/lastUpdated 반영 확인.
   - VehicleStatus/status.json, targetInfo.json, push_store(0902) 저장 위치가 current_scenario.json에서 지정한 Logs/<Scenario>/SBC3 하위인지 검증.

남은 확인/보완 메모
- 위치 기반 스케줄링/비행경로 결정 로직의 상세(SDD 명시)와 TRR 데모 데이터 세트(0401 좌표→경로 변경)를 준비하면 요구 1.2 증빙이 강해짐.
- availability 재계산은 health/좌표/연료가 모두 필요하므로 테스트 메시지에 필드 누락이 없도록 시나리오 파일을 준비.
