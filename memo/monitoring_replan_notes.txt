모니터링 모듈 재계획 판단/트리거 세부 정리 (ver2 기준)
- 참조: modules/monitoring/manager.py, modules/monitoring_ver2/logic/monitoring_logic.py, modules/monitoring_ver2/logic/monitoring_logic_part.py, modules/monitoring_ver2/logic/replan_actual_logic.py
- 시스템 모드는 3(임무 수행)에서 상시 루프, 4에서 1회 실행 후 mode=1로 복귀. 루프는 monitoring_logic.execute → replan_logic.execute(run_replan_procedure) 순으로 동작.
- 재계획 흐름: ReplanSituations 큐에 트리거를 쌓고 → manage_replan_triggers가 우선순위(운용자/강제 우선)로 하나를 ConfirmedReplanRequest로 선택 → determine_level_and_send_request가 0902를 생성/송신하고 final_replan_output 갱신.

1) 운용자/강제 명령 기반(추가 입력 카테고리)
- 0801 운용자 임무재계획 명령: 새 timestamp 수신 시 judge_replan_situation이 ReplanSituations에 추가. replanLevel=1, replanReason은 payload.replan_reason 또는 기본 “운용자 명령”.
- 0802 강제명령: mandatoryType별 처리
  - 1(강제대기): _handle_mandatory_command가 10초 지연(deadline, reason 저장) 후 judge_replan_situation에서 재계획 후보로 사용. 대기 중에는 availability를 off.
  - 2(강제귀환), 3(임무 재투입/복귀): 즉시 가용여부 반영, 필요 시 _trigger_replan_if_active로 재계획 루프 실행. manage_replan_triggers에서 operator 계열로 분류되어 replanLevel=1. 0902에 제외 항공기 ID가 반영됨.
- 우선순위: manage_replan_triggers는 상황 텍스트에 “운용자/강제”가 포함된 항목을 먼저 선택.

2) 협업/입력 변화 기반(입력 업데이트/명령 카테고리)
- 0803 다음 협업기저임무 수행 명령:
  - execute=2: 협업 일시정지 모드 진입, _register_collab_replan_trigger(source=payload.source, replanLevel 기본 3, reason=COLLAB_REPLAN_REASON_REEXECUTE), 즉시 _maybe_stage_replan 호출.
  - execute=1: 대기된 입력 임무 완료 큐를 적용하고 다음 입력 임무로 진행, pending replan 취소.
  - 기타 execute: 협업 일시정지 해제 및 pending replan 취소.
- 0201 InputMissionPlan 갱신:
  - SystemMode 3/4에서 packageID/timestamp 변화 감지 시 _register_input_plan_refresh_trigger(source=payload.Source, replanLevel=3, reason=COLLAB_REPLAN_REASON_REINPUT) 후 _maybe_stage_replan 호출.
  - _maybe_stage_replan은 pending 상태일 때만 동작하며, 동일 packageID+timestamp 중복/갱신 조건을 확인한 뒤 _build_replan_body로 0902 payload를 구성(옵션: 시스템추천/기여효율/생존효율, replanLevel=trigger 값, replanRequestTime=now).
  - _dispatch_collab_replan가 0902 push 후 collab_replan_state/logic_store 갱신, _collab_replan_inflight=True. 0305 상태 2 수신 시 _finalize_collab_replan로 완료 처리.

3) 상황인식/룰 기반 자동 판단(시스템 판단 카테고리)
- 0402 Situation Awareness(targetInfo) 수신:
  - _process_target_replan_candidates: actionable 조건(unknown- key 아님, targetID 존재, isUsed/isIgnored=0, isDestroyed=False)을 만족하고 lastUpdated가 새로울 때 payload를 생성.
    · REPLAN_FIELD_SITUATION=“0402 타겟 재계획”, REPLAN_FIELD_REASON=“관제콜사인 - 목표유형(ID-x) 추가탐지로 인한 재계획”, detail에 trigger=0402/targetKey/targetID/watchers/좌표/스냅샷 포함, preferredOptionCount=3.
    · mark_targets_as_used로 isUsed=1 처리 후 ReplanSituations에 push, replan_triggers 즉시 노출, SystemMode 3/4이면 run_replan_procedure 호출.
  - new_detections가 존재하지만 actionable 추가 없음: 재계획이 아직 안 돌았으면 _trigger_replan_if_active 호출(실제 상황 판단은 run_replan_procedure에서 큐를 확인).
- ROI caution 타임아웃:
  - unknown-* ROI가 존재하면 caution 상태 ON, ROI_CAUTION_TIMEOUT_SECONDS=1000s 타이머. 타임아웃 시 _build_roi_replan_payload(trigger=0402_ROI, reason=“관제콜사인 ROI 경고 지속(count=n)”, detail에 ROI 스냅샷/타이머 정보) 추가 후 재계획 실행.
- 0802와 결합된 룰: mandatoryType=1 대기 후 10초 경과, 또는 mandatoryType=3 복귀 명령이 대기 타이머 안에 들어오면 재계획 스킵/지연 처리(hold_state와 resume_requested_timestamp로 제어).

4) 재계획 요청 생성 규칙/출력(0902)
- replanLevel 결정: replan_situation에 “운용자/강제” 포함 또는 msg 0801/0802이면 1, 그 외 run_replan_procedure 경로는 2. 협업 경로(_dispatch_collab_replan)는 trigger에 설정된 값(기본 3).
- inputMissionID 선정(_collect_replan_inputs):
  - monitoring_logic._plan_context의 진행 상태/완료 여부, 가용 항공기, 제외 항공기(0802) 정보를 반영해 미완료 inputMissionID를 우선 선택.
  - 없으면 현재 InputMissionPlan 파일에서 isDone=False인 항목을 추출, 마지막 수신 InputMissionPlan이 없을 경우 최근 DB 기록을 로드. target 트리거일 때는 plan_context에서 남은 inputMissionID로 교체.
- optionList:
  - target 트리거: optionID 4/5(“공격 강화”, “공격 배제”) + missionPlanID 중앙 발급.
  - 협업 트리거: 시스템추천/기여효율/생존효율 옵션 + missionPlanID 발급.
  - 기타 기본값: 옵션 A/B/C + missionPlanID 발급.
- replanReason:
  - 명시적 REPLAN_FIELD_REASON이 있으면 사용, 없을 때 0801/0802는 사전에 정의된 텍스트(운용자 명령, 강제대기/귀환/임무복귀), 그 외에는 replan_info JSON 직렬화.
  - detail payload(dict) 존재 시 0902에 replanDetail로 포함.
- 추가 데이터: 0902 push 후 final_replan_output에 replan_status="TRIGGERED"/situation/입력ID/옵션 planID/제외 항공기 정보 저장, target trigger 시 mark_targets_as_used로 중복 방지.
