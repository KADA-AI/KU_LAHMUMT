# 수정규칙 (AI 코드 수정 시 반드시 준수)

이 문서는 사람이 아니라 **이 저장소를 수정하는 AI 에이전트**를 위한 규칙이다.
`modules/` 아래 코드를 고치기 전에 먼저 읽고, 아래 3가지를 어기지 말 것.

형상관리 범위는 `modules/`, `settings/`, `run.py` 뿐이다.
`resource/`, `docs/`, `Logs/`, `test/` 는 git 미추적(로컬 참고자료)이므로
"저장소에 없다 = 없는 파일"로 착각하지 말 것.

---

## 1. 버전 기록 — 파일을 수정했으면 반드시 남긴다

### 어디를 고쳐야 하나

**고칠 곳은 단 하나: [`modules/change_log.md`](change_log.md) 의 맨 첫 줄이다.**

루트 `run.py`에는 버전이 없다. 버전 문자열이 실제로 살아 있는 경로는 다음과 같다:

```
modules/change_log.md  (첫 유효 줄 = 단일 진실 원천)
        │
        └─ modules/common/version_info.py : load_release_info()   ← 파싱만 함
                │
                ├─ modules/run.py : RUNPY_GUI_UPDATE_VERSION / _DATE / _NOTE   (런처 GUI 표시)
                └─ write_scenario_version_log() → Logs/Scenario_*/DSS_KU_VERSION.json  (실행 기록)
```

즉 `change_log.md` 첫 줄만 고치면 런처 GUI 표기와 시나리오 실행 로그가 **자동으로** 따라온다.

### 절대 손대지 말 것

- `modules/run.py`의 `RUNPY_GUI_UPDATE_VERSION` / `RUNPY_GUI_UPDATE_DATE` / `RUNPY_GUI_UPDATE_NOTE`
  → `load_release_info()` 결과를 받아 쓰는 파생값이다. 여기에 버전을 하드코딩하면 이중 관리가 된다.
- `modules/common/version_info.py`의 `_FALLBACK_VERSION` / `_FALLBACK_RELEASE_DATE`
  → `change_log.md`를 **읽지 못했을 때만** 쓰이는 비상값이다. 평상시 갱신 대상이 아니다.

### 기록 형식 (형식이 깨지면 그 줄은 무시되고 옛 버전이 표시된다)

```
YYYY-MM-DD vX.Y.Z - 한 문단 요약
```

파서 정규식은 `modules/common/version_info.py`의 `_RELEASE_LINE_RE`:
`^(\d{4}-\d{2}-\d{2})\s+(v?\d+(?:\.\d+)+)\s+-\s*(.*)$`

- 날짜는 `YYYY-MM-DD`, 버전 앞의 `v`는 붙인다.
- 날짜와 버전, 버전과 `-` 사이는 공백. `-` 뒤에 요약.
- **줄바꿈 금지.** 요약이 길어도 한 줄로 쓴다. 다음 줄로 넘기면 파싱이 끊긴다.

### 버전 올리는 법

- 패치 자리 **+0.0.1**. 예: `1.4.1` → `1.4.2` → `1.4.3`.
- 새 항목은 **파일 맨 위**에 삽입하고, 기존 첫 항목과 **빈 줄 하나**로 띄운다.
- 요약에는 (1) 무엇을 바꿨는지, (2) 왜 바꿨는지, (3) 무엇으로 검증했는지를 담는다.
  기존 항목들의 서술 밀도를 그대로 따라간다.

### 작성 예

```
2026-07-28 v1.4.3 - AREA 재계획 시 이전 커버리지가 초기화되던 문제를 수정함. 플랜 전환 경로에서 covered 집합을 이월하도록 바꾸고, 전환 직후 진행률이 0으로 떨어지지 않음을 2기체 회귀 시나리오로 확인함.

2026-07-25 v1.4.1 - 지상작전부대(type=2)의 ...
```

## 2. DEM 사용 규칙

### 운용 DEM은 아래 3개뿐이다

| 파일 | 해상도 | 비고 |
|---|---|---|
| `resource/Inje_10m.tif` | 10 m | 최우선 (고해상도) |
| `resource/Hongik_48km.tif` | 30 m | |
| `resource/Jipo_48km.tif` | 30 m | |

세 파일 모두 **EPSG:32652** 투영이다.

### 지켜야 할 것

- **경로를 직접 하드코딩하지 말 것.** 반드시
  [`modules/common/regional_dem.py`](common/regional_dem.py) 레지스트리를 통해 접근한다.
  - `select_regional_dem(lat, lon)` — 좌표를 포함하는 DEM 선택
  - `regional_dem_paths(resource_dir)` — 존재하는 DEM을 우선순위대로
  - `regional_dem_inventory(resource_dir)` — 기대/실존 목록 진단
  - `REGIONAL_DEM_SPECS` / `REGIONAL_DEM_FILENAMES` / `REGIONAL_DEM_EPSG_BY_NAME`
- **우선순위는 `Inje_10m.tif`가 먼저**다. 파일명 정렬 순서로 고르면 저해상도가 선택된다.
- `resource/n3x_e12x_1arc_v3.tif` 같은 SRTM 1arc 도분 타일이나 `korea.mbtiles`로
  **조용히 폴백하지 말 것.** 운용 DEM이 없으면 명시적으로 경고/실패시킨다.
- DEM 좌표 판정을 계획기와 SIM이 **다르게** 하면 실기체에서 정지·무한루프가 난다.
  지형 고도·LOS 판정을 새로 추가할 때는 기존 공유 커널(`terrain_los.py` 등)을 재사용한다.
- 성능: DEM 경로 resolve와 런타임설정 복사가 반복 호출의 실제 병목이다.
  루프 안에서 매번 경로를 다시 찾지 말고 캐시된 핸들을 넘긴다.
- `resource/`는 git에 없다. 새 개발 환경에서는 위 3개 파일을 별도로 배치해야 한다.

## 3. ICD(메시지) 규칙

### 기준 문서

**`docs/reference/MessageLibrary_건대송부`** 가 ICD의 단일 기준이다.
메시지 번호별 디렉터리(`msg_0000` … `msg_0904`)에 `.nftype` / `.nfpsh` 정의가 있고,
`CommonType`, `InternalMessage`, `bin` 이 함께 들어 있다.

### 지켜야 할 것

- 메시지 필드를 추가·변경·해석하기 전에 **반드시 해당 `msg_XXXX` 정의를 먼저 확인**한다.
  필드명·타입·enum 값을 추측해서 만들지 말 것.
- `modules/common/generator/messageXXXX_generator.py` 와
  `modules/common/receive/messageXXXX_receiver.py` 는 **자동 생성물**이다
  (파일 머리에 `# auto-generated at ...` 표기).
  → 여기에 손으로 넣은 ICD 수정은 **코덱을 재생성하면 소실된다.**
  부득이하게 수동 수정하면 무엇을 왜 고쳤는지 `change_log.md`에 남겨 재생성 시 복원 가능하게 한다.
- 생성 규칙은 `modules/common/nFusion_MessageLIbrary/rules/`
  (`field_profiles.txt`, `conditions.txt`)를 참조한다.
- 바이너리 라이브러리는 `modules/common/msg_files/`
  (`MessageLibrary.dll`, `K4586Model.dll` 등). 버전이 다른 사본
  `modules/common/msg_files_0713/` 와 혼용하지 말 것.
- `docs/reference/`도 git 미추적이다. 기준 문서가 갱신되면 로컬 사본을 먼저 최신화한 뒤 작업한다.
