재계획 상황 구현 내용

1. 0802 강제명령

1) execute 2(강제귀환)일때 -> 가용정보 업데이트 후 -> 바로 재계획 들어감
 * 재계획 규칙
  - 지금까지 한 임무를 기반으로 새로운 영역 생성 -> 임무 수행 상태에 대해 영역을 모니터링하고 추후 쓰는 방안이 필요함(계획정보, 그리고 찍어야하는 정보로 만들면 될 듯)
  - 가용한 기체에대해 할당
  - 임무 재계획 수행
  => 일단 임시로, 지금까지 한 협업기저 임무 파악 후, 협업기저임무 다시 계획함 


2) execute 1(강제대기)일때 -> 20초간 일단 지켜봄 -> 20초 내에 execute에 대한 다른 명령 없을경우 재계획 들어감
 * 재계획 규칙
  - 지금까지 한 임무를 기반으로 새로운 영역 생성
  - 가용한 기체에대해 할당
  - 임무 재계획 수행

3)  execute 3(임무로 복귀)일때 -> 해당 소티 개별임무에 다른 비행체와의 임무 종료시간 차이가 심하지 않은지 확인 -> 임무 재할당 필요여부 식별
ㄴ 필요할 경우? -> 남은 영역을 다른 무인기가 같이 해주는 형태로
ㄴ 필요 없을경우? -> 그냥 남은거 그대로 하게끔(재계획 안함) 
ㄴ 이미 앞의 상황으로 인해 임무를 하고있는데 갑자기 투입됐다?? -> 해당 무인기 위치보고 -> 임무 지점 이동 시간 계산 -> 다른 무인기의 임무 프로그래스 예측해보고 30퍼 미만이면 한것까지만 하고 남은 부분 재계획 하는걸로


2. 0801 운용자 임무재계획 명령

1) 운용자가 보내주는 InputMissionPackageID / MissionReferencePackageID를 사용해서 임무 재계획을 프로세스를 수행


3. 0402 상황인지에 대한 부분?

상황 1) ROI가 뜬 상태(탐지만 됨) -> 모니터링에서는 주의(caution) 모드 On
Target 발견 주의 모드 On에서 10초간 기다렸는데 모드가 여전히 On이다? -> 재계획 수행(발견 위치 주변으로 영역 생성하여 촬영 임무 추천(시스템 추천))

상황 2) Target List가 들어온 상태 -> 모니터링에서 경로(warning) 모드 On
Target이 발견된 상황 -> 해당 무인기는 추적 시작(300초?) -> 해당 무인기를 포함한 새로운 임무 생성이 필요함!

상황 3) ROI가 뜬 상태(탐지가 됨) -> Target List가 들어온 상태(상황 2와 동일)


4. 0202 선행임무에 대한 부분? 

1) 선행임무가 입력되었다?? 즉시 임무 재계획 명령 보냄(현재 구현 되어있음)

2) 임무계획 GUI가 0902를 받으면 파이프라인을 도는 동안 replanLevel을 확인해 level 4일 때는 전송 루틴을 바꾸고 있음

이때 재계획 시 Flight Path 부분에만 변경을 하는 전략이 필요함 -> 0202를 위한 pipeline 파일 따로 만들어서 관리할 것

좌표지향에 대한 재계획 파이프라인이 돌 경우, DB 폴더에 Logs\....\SBC3\DSS_Internal 안에 PriorMission(IDNum).json을 만들어 임무계획 과정을 기록 및 로깅해줘
