Mission Planning Manual Test Scenarios
작성일: 2026-06-05

목적
- 리팩터링 후 임무계획 기능 변화가 없는지 수동으로 하나씩 확인한다.
- 특히 초기 임무계획, 재계획, 공격/촬영/경로 산출물, wrapper/import 호환성을 확인한다.

공통 확인 위치
- 실행 로그: Logs/Scenario_*/SBC3/
- 내부 상태: Logs/Scenario_*/SBC3/DSS_Internal/
- 주요 산출물: 0301, 0302, 0303, 0304, 031x, 0902, 53111, 53112, 53120
- 임무계획 코드: modules/mission_planning/

0. 기본 실행 확인
- 기존 방식대로 앱을 실행한다.
- mission planning 화면이 열린다.
- ImportError, ModuleNotFoundError, circular import 오류가 없어야 한다.
- modules/mission_planning 루트에는 public launcher/wrapper 중심으로만 남아 있어야 한다.

1. 초기 임무계획 생성
- 기본 시나리오로 초기 임무계획을 수행한다.
- 0301/0302/0303/0304 및 53111/53112 산출물이 생성되는지 확인한다.
- missionSegmentN, individualMissionListN, waypointListN 값이 실제 list 길이와 맞는지 확인한다.
- waypointID가 0으로 남지 않아야 한다.
- nextWaypointID 체인이 마지막 WP까지 정상 연결되고 마지막은 0이어야 한다.

2. 넓은 지역 정찰/촬영 영역
- 넓은 area mission이 포함된 시나리오를 수행한다.
- 넓은 영역인데 waypointList가 1개로만 끝나는지 확인한다.
- 단일 WP라도 촬영 coordinateList가 충분한지, 또는 현재 코드 기준으로 최소 2개 WP 체인으로 보정되는지 확인한다.
- WP speed와 filmingProperty.searchSpeed를 구분해서 확인한다.
- WP speed가 입력/설정 대비 비정상적으로 낮거나 높지 않아야 한다.
- 촬영 coordinateListN이 실제 coordinateList 길이와 같아야 한다.

3. 경로 이탈 재계획
- UAV 경로 이탈 상황을 만든 뒤 재계획을 요청한다.
- 0902 요청이 기록되고 path deviation replan pipeline이 실행되는지 확인한다.
- 새 0303/53112 산출물이 생성되는지 확인한다.
- 기존 완료/진행 임무가 임의로 사라지지 않아야 한다.
- 새 waypointID가 기존 ID와 충돌하지 않아야 한다.

4. 다음 협업/다음 영역 재계획
- 현재 임무 완료 또는 다음 협업 상황을 발생시킨다.
- next collab replan pipeline이 실행되는지 확인한다.
- 새 임무만 바뀌고 이전 임무 상태가 불필요하게 초기화되지 않아야 한다.
- DSS_Internal/next_collab_replan/ 쪽 상세 로그가 남는지 확인한다.
- 중복 missionSegmentID 또는 누락 missionSegmentID가 없어야 한다.

5. 촬영 스케줄 재계획
- 촬영 지연/스케줄 변경 상황을 만든다.
- imaging schedule replan pipeline이 실행되는지 확인한다.
- 촬영 대상, coordinateList, searchSpeed, waypoint chain이 유지되는지 확인한다.
- 촬영과 무관한 공격/복귀 임무가 바뀌지 않아야 한다.

6. 공격 임무 계획
- 표적 공격 임무가 포함된 시나리오를 수행한다.
- 0304/53111 산출물이 정상 생성되는지 확인한다.
- attack assignment state가 DSS_Internal에 기록되는지 확인한다.
- 공격 후 다음 임무 또는 재계획으로 넘어갈 때 임무가 중복 전송되지 않아야 한다.
- direct delivery suppression 관련 로그가 의도대로 찍히는지 확인한다.

7. 실행 중 상태/캐시/로그
- latest input cache가 0201/0203 최신 입력을 잘 참조하는지 확인한다.
- id_tracker, waypoint_usage, path_usage가 깨지지 않는지 확인한다.
- Scenario별 로그가 해당 Scenario 폴더 아래에만 생기는지 확인한다.
- 프로젝트 루트에 불필요한 새 산출물이 생기지 않아야 한다.

8. 이전 import 경로 호환성
- 기존 코드가 MissionPlanner/data_def/d0303.py 같은 옛 경로를 import해도 동작하는지 확인한다.
- 실제 active module은 engine/mission_generation/... 쪽으로 연결되어야 한다.
- legacy/manual 폴더의 수동 도구는 자동 런타임 경로와 섞이지 않아야 한다.

10. 테스트 중 바로 기록할 이상 징후
- ImportError 또는 특정 폴더를 못 찾는 오류
- missionSegmentID 누락/중복
- waypointID 0 잔존 또는 nextWaypointID 끊김
- 넓은 area mission의 waypointListN이 1로 고정되는 현상
- coordinateListN과 실제 coordinateList 길이 불일치
- 53112 또는 53111이 생성되지 않는 현상
- 기존 완료 임무가 재계획 후 사라지는 현상
- Logs 외부에 런타임 산출물이 새로 생기는 현상
