재계획 상황 정리
=================

본 문서는 현재 구현된 재계획 트리거와 대응 절차를 상황 중심으로 요약한 것이다. 각 항목은 (1) 상황 설명(예시 시나리오), (2) 판단 로직/근거 데이터, (3) Output(진행되는 파이프라인과 산출물)로 구성되어 있다.

1. 0802 execute 2 ― 강제귀환 즉시 재계획
--------------------------------------
- **상황 설명**: 정찰 A/B 두 대가 협업 중 A가 엔진 이상으로 즉시 귀환 명령을 받는다. 남은 감시 구역은 비어 있고 B만 현장에 남는다.
- **판단 로직**: 0802 메시지에서 `execute=2` 감지 시, 가용 정보 업데이트 후 즉시 재계획 모드 진입. 지금까지 수행한 임무 궤적을 기반으로 새로운 ROI를 생성하고, 현재 임무 진행 상태/잔여 목표를 모두 수집한 뒤 가용 기체를 재할당한다.
- **Output**: GUI `mission_planning_gui._schedule_replan_pipeline()`이 호출되어 `_run_replan_pipeline_do`에 진입한다. 여기서 0305 상태 1을 Push 후, Prior Mission 파이프라인 시도 → 일반 divide&pattern/0301 생성으로 이어지며 새 임무 패키지(0201/0203)와 로그 세션이 생성된다.

2. 0802 execute 1 ― 강제대기 후 재시작 감시
--------------------------------------
- **상황 설명**: 감시 중이던 소티가 야간 교신 불안정으로 20초간 대기 지시를 받는다. 20초 동안 추가 명령이 없으면 자체적으로 남은 임무를 재설계해야 한다.
- **판단 로직**: `execute=1` 수신 후 20초 타이머 동작. 같은 대상에 대한 추가 명령이 없으면 재계획을 수행한다. 데이터 취득 방식은 실행 2와 동일하게 “지금까지의 임무 기반 ROI 재생성 → 가용 기체 재배치” 순서를 따른다.
- **Output**: 1번과 동일한 재계획 파이프라인이 실행되며, 타이머 조건이 만족될 때까지는 파이프라인이 지연된다. 결과적으로 새 0301 경로 세트만 갱신되므로 운용자는 GUI 로그의 `[AUTO] replan pipeline scheduled ...` 및 `[OPS] 0305 ...` 메시지로 상태를 확인한다.

3. 0802 execute 3 ― 임무 복귀/부분 재할당
-----------------------------------
- **상황 설명**: 세 대가 구역을 나누어 촬영 중인데, 임무 복귀 명령이 내려오면서 한 대가 중간에 빠진다. 남은 구역을 다른 기체가 이어 받아야 한다.
- **판단 로직**: `execute=3` 수신 시 각 개별 임무의 종료 예상 시간을 비교해 재할당 필요 여부를 판단한다. 30% 미만만 소화했거나 다른 기체가 더 빠르게 도착할 수 있다면 남은 구간만 잘라 재계획한다. 현재 위치, 경로 이동 시간, 타 기체 진행률 데이터를 함께 사용한다.
- **Output**: 필요 시 협업 구간만 분리한 재계획 패키지를 생성한다. Prior Mission 파이프라인이 성공하면 `modules/mission_planning/prior_mission_pipeline_impl.py`의 “선행임무 재계획” 옵션으로 처리되고, 그렇지 않으면 일반 재계획 파이프라인으로 넘어간다.

4. 0801 운용자 재계획 명령
------------------------
- **상황 설명**: 운용자가 특정 목표에 대해 수동으로 새 임무 패키지를 업로드하고, 기존 계획을 덮어쓰도록 명령한다.
- **판단 로직**: 0801 메시지에서 전달된 `InputMissionPackageID`, `MissionReferencePackageID`를 GUI `_stage_plan_context()`에 저장하고 `reason`을 운용자 지정 값으로 유지한다.
- **Output**: `_ensure_ctx_package_ids()`가 두 패키지 ID를 그대로 사용해 신규 0301/0302/0303 데이터를 구성한다. 필요 시 `_should_use_attack_pipeline()`이 공격 특화 파이프라인을 실행하며, 최종적으로 `build_mission_plan_0301` 호출을 통해 산출된 임무가 0301 송신 루틴으로 전파된다.

5. 0402 상황인지 트리거 (ROI/Target List 기반)
------------------------------------------
- **상황 설명**: 감시 구역 ROI가 끊겨 모니터링 모듈이 caution 모드를 켜고 10초 동안 복구되지 않는다. 혹은 Target List가 warning 모드로 들어오고 특정 무인기가 300초 추적 모드에 들어간다.
- **판단 로직**: 0402 메시지에서 ROI 비활성화 상태와 Target List 진입 여부를 모니터링한다. caution 모드가 10초 이상 지속되거나 warning 모드가 켜지면 재계획 조건을 만족한 것으로 간주한다.
- **Output**: 자동으로 탐지 위치 주변에 새로운 영역을 생성해 촬영 임무를 추천한다. GUI 로그에는 `[AUTO] replan ...` 흐름이 동일하게 남으며, 추천 임무는 divide&pattern 파이프라인이 생성한 신규 경로로 표현된다.

6. 0202 선행임무/좌표 기반 재계획
------------------------------
- **상황 설명**: 0202 패킷으로 좌표 한 점이 들어오면서 “해당 위치 최접근 기체가 급히 확인”이라는 지시가 떨어진다.
- **판단 로직**:
  1. 0202 수신 즉시 재계획 명령을 발행한다.
  2. GUI는 0902 처리 중 `replanLevel=4`일 경우 송신 루틴을 특수 모드로 변경해 Flight Path만 수정한다.
  3. Logs/.../DSS_Internal 폴더에 `PriorMission(ID).json`을 생성해 과정과 결과를 로깅한다.
  4. Step-by-step: (a) 모든 기체의 현재 WP(0401 기반)를 확보한다. (b) 0202 좌표를 활용해 가장 가까운 기체를 선택한다. (c) 해당 기체가 추종 중인 WP 바로 앞에 새로운 WP를 삽입하고 `modules/mission_planning/MissionPlanner/data_def/id_allocator.py`로 ID를 부여한다. (d) 새 WP는 Loiter 타입, FOV 5°, 좌표지향 모드 등 요구 값을 반영한다.
- **Output**: Prior Mission 파이프라인이 우선적으로 실행되어 “선행임무 재계획” 옵션이 로그에 남는다. 새 Flight Path 파일(예: `400000003.json`)과 연결된 IndividualMissionPlan ID가 함께 갱신되고, 0305/0702 시퀀스를 통해 운용자 화면에 재계획 완료가 표시된다.

7. 전체 파이프라인 상태/로깅
-----------------------
- **상황 설명**: 재계획이 트리거되면 운용자는 GUI와 run.py 로그를 통해 진행 상황을 모니터링해야 한다.
- **판단 로직**: 0305 메시지 `missionPlanningStatus` 값(0: 진행, 1: 완료)을 기반으로 run.py가 `[OPS] 0305 ...` 로그를 출력하며, 0702가 들어올 때 대기 모드로 전환한다.
- **Output**: `mission_planning_gui`는 재계획 세션을 열고 `_pipeline_logger`에 reason/plan_ids/replan_level을 기록한다. 공격 특화 파이프라인(`run_attack_plan_pipeline`)과 Prior Pipeline을 통과한 뒤, 최종 divide&pattern → `build_mission_plan_0301` → 0301 송신 루틴으로 마무리된다.
